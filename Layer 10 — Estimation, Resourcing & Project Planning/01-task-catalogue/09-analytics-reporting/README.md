# 1. Purpose

This directory contains the task-decomposable implementation catalogue for the Layer 2 Analytics, Reporting & Data Visualisation capability domain.

Each capability is represented by an individual Markdown file containing:

- Capability metadata
- Capability objective
- Layer 1 phase mappings
- Source implementation activities
- Atomic implementation tasks
- Task IDs
- Task classifications
- Primary delivery roles
- Customer responsibilities
- Environment requirements
- Automation considerations
- Baseline effort
- Dependencies
- Deliverables
- Acceptance criteria
- Critical path indicators
- Capability-level dependencies
- Capability-level estimation considerations
- Definition of Done

The catalogue is intended to provide the source material for:

- Detailed project schedules
- Work breakdown structures
- Resource planning
- Effort estimation
- Statements of Work
- Delivery plans
- Project governance
- Customer responsibility matrices
- Spreadsheet-based estimation models

# 5. Standard Task ID Convention

```text
L10-09-CC-###
```

Where:

- `L10` = Layer 10
- `09` = Analytics, Reporting & Data Visualisation
- `CC` = capability number
- `###` = sequential implementation task

Example:

```text
L10-09-08-001
```

---

# 6. Standard Task Structure

Every capability file must use the established Layer 10 task structure.

Each implementation task must include:

- Task Type
- Layer 1 Phase
- Primary Role
- Customer Responsibility
- Environment
- Automation
- Baseline Effort
- Critical Path
- Description
- Dependencies
- Deliverable
- Acceptance Criteria

---

# 7. Estimation Principle

Tasks are intentionally atomic enough to be converted into spreadsheet rows.

The catalogue should therefore avoid combining unrelated implementation activities into a single task.

Where appropriate, a capability should contain separate tasks for:

1. Requirements
2. Design
3. Configuration
4. Integration
5. Validation
6. Documentation
7. Handover

---

# 8. Classification

Capabilities and tasks should be classified as:

- REQUIRED
- CONDITIONAL
- OPTIONAL
- VALIDATION

Conditional capabilities should only be estimated when the corresponding solution scope requires them.
