# Layer 10 — 04 ACD & Routing Task Catalogue

## Purpose

This directory contains the implementation task catalogue for **Layer 2 — 04 ACD & Routing**.

The catalogue decomposes the ACD and routing capability domain into implementation activities and individually estimable implementation tasks.

The structure follows the established Layer 10 task-file standard used by `01-core-platform` and `02-identity-access`.

## Task Standards

Every capability file contains:

- Capability reference
- Capability objective
- Layer 1 mapping
- Source implementation activities
- Numbered implementation tasks
- Task type
- Layer 1 phase
- Primary role
- Customer responsibility
- Environment
- Automation approach
- Baseline effort
- Critical-path indicator
- Dependencies
- Deliverables
- Acceptance criteria
- Capability-level dependencies
- Estimation considerations
- Definition of Done

## Task Types

| Task Type | Meaning |
|---|---|
| REQUIRED | Expected for a normal implementation |
| CONDITIONAL | Required only when the applicable design or solution requires it |
| OPTIONAL | Useful enhancement but not mandatory |
| VALIDATION | Verification or testing activity |
| MIGRATION | Existing-state migration or cutover activity |
| OPERATIONAL | BAU, support or operational-readiness activity |

## Estimation Use

The individual tasks are intended to become the source data for:

- project schedules
- work breakdown structures
- effort estimates
- resource plans
- implementation statements of work
- delivery dashboards
- critical-path analysis
- customer responsibility matrices
- implementation spreadsheets

Baseline effort values are indicative starting points and must be calibrated against actual project complexity.
