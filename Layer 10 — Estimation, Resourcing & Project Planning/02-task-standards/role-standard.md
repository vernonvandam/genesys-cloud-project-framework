# Layer 10 — Role Standard

## Purpose

This document defines how delivery roles are assigned to implementation tasks.

---

# 1. Primary Role

Every task must have one Primary Role.

The Primary Role is accountable for executing or coordinating completion of the task.

---

# 2. Supporting Roles

Additional supporting roles may be identified where necessary.

Examples:

```text
Primary Role:
Genesys Cloud Engineer

Supporting Roles:
Solution Architect
Customer SME
Security Specialist
```

---

# 3. Role Assignment Principles

Role assignment should consider:

- technical competency
- accountability
- task complexity
- required platform knowledge
- customer responsibility
- security requirements
- integration ownership
- environment access

---

---

# 5. Primary Role vs Resource

A Primary Role is a capability classification.

A resource is an actual person or assigned delivery resource.

Therefore:

```text
Primary Role
      ↓
Role Catalogue
      ↓
Resource Type
      ↓
Actual Project Resource
```

Task Standards must not embed individual names.

---

# 6. Customer Roles

Customer roles may be identified where the customer owns:

- requirements
- approvals
- data
- testing
- business validation
- production access
- operational readiness
- acceptance

---

# 7. Role Changes

Changing a task's Primary Role may affect:

- effort
- cost
- schedule
- dependencies
- resource loading

Such changes should therefore be assessed as part of project planning.

---

# 8. Definition of Done

Role assignment is complete when:

- one Primary Role is defined
- supporting roles are identified where needed
- role is appropriate to the task
- customer roles are distinguished from delivery roles
- role classification aligns with Layer 10/04
