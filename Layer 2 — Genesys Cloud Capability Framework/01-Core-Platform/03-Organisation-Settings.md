# Layer 2.01.03 — Organisation Settings

## Capability Definition

Defines organisation-level configuration required to establish the platform baseline.

---

# 1. Scope

- Organisation settings
- Default configuration
- General platform preferences
- Administrative settings
- Global configuration
- Platform policies where applicable

---

# 2. Classification

**Required**

Specific settings are conditional based on the project scope.

---

# 3. Discovery

Determine:

- Existing configuration.
- Required defaults.
- Customer standards.
- Administrative requirements.
- Security requirements.
- Naming standards.
- Data requirements.
- Operational requirements.

---

# 4. Implementation Activities

```text
Review organisation settings
Document current state
Define target state
Configure required settings
Validate defaults
Validate administrative access
Document configuration
```

---

# 5. Dependencies

- Organisation
- Architecture
- Security
- Licensing
- Environment strategy

---

# 6. Layer 1 Mapping

Primary:

- Phase 4 — Architecture
- Phase 5 — Platform Foundation

Supporting:

- Phase 8 — Testing

---

# 7. Roles

- Genesys Cloud Architect
- Genesys Cloud Engineer
- Security Architect

---

# 8. Testing

- Validate settings.
- Validate access.
- Validate expected defaults.
- Validate downstream behaviour.

---

# 9. Deliverables

- Organisation settings design
- Configuration
- Configuration evidence

---

# 10. Effort Drivers

- Existing configuration
- Number of settings
- Security requirements
- Governance
- Automation

---

# 11. Acceptance Criteria

All approved organisation-level settings are configured and validated.

---

# 12. Definition of Done

Approved organisation settings are implemented, tested and documented.
