# Layer 2.04.05 — Queue Membership

## 1. Purpose

Define which users are members of each queue and therefore eligible for interaction delivery.

## 2. Classification

**Required**

## 3. Discovery

Determine:

- User-to-queue mappings
- Primary queues
- Secondary queues
- Temporary memberships
- Supervisor requirements
- Division restrictions

## 4. Activities

- Build membership matrix.
- Validate user identities.
- Validate divisions.
- Configure queue membership.
- Test agent eligibility.
- Test routing.
- Validate exceptions.

## 5. Risks

- Users routed interactions for which they are not trained.
- Users excluded from required queues.
- Incorrect division assignment.

## 6. Acceptance Criteria

Queue membership matches the approved user/queue matrix.

## 7. Definition of Done

Queue membership is configured, validated and documented.
