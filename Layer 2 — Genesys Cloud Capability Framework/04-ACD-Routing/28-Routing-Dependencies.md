# Layer 2.04.28 — Routing Dependencies

## 1. Purpose

Identify all dependencies that influence routing behaviour.

## 2. Classification

**Required**

## 3. Dependencies

Potential dependencies include:

- Architect flows
- Data Tables
- Data Actions
- CRM
- Customer identity
- User attributes
- Skills
- Schedules
- Holidays
- Presence
- Workforce Management
- Customer journey information
- External APIs

## 4. Activities

- Inventory dependencies.
- Define dependency owner.
- Define interface.
- Define failure behaviour.
- Test successful dependency.
- Test failed dependency.
- Document recovery.

## 5. Acceptance Criteria

Routing remains predictable under expected dependency failure conditions.

## 6. Definition of Done

Routing dependencies are documented, configured and tested.
