# Layer 2.05.07 — Common Modules

## Purpose

Create reusable Architect components to reduce duplication and simplify maintenance.

## Classification

**Required**

## Potential Components

- Customer identification
- Authentication
- Common prompts
- Error handling
- Business-hours handling
- Customer lookup
- Language selection
- Queue transfer
- Callback
- Standard announcements

## Activities

- Identify reusable logic.
- Define module interfaces.
- Define inputs.
- Define outputs.
- Build Common Modules.
- Test independently.
- Integrate into flows.
- Regression test dependent flows.

## Acceptance Criteria

Common Modules operate consistently across consuming flows.

## Definition of Done

Reusable modules are documented, tested and production-ready.
