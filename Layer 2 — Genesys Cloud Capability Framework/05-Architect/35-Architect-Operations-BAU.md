# Layer 2.05.35 — Architect Operations & BAU

## Purpose

Establish the operational model for maintaining Architect after production deployment.

## Classification

**Required**

## Scope

- Flow changes
- Prompt changes
- Data Table changes
- Data Action changes
- Schedule changes
- Holiday changes
- Emergency changes
- Troubleshooting
- Monitoring
- Reporting
- Incident management
- Change management

## Activities

- Define support ownership.
- Define L1/L2/L3 responsibilities.
- Define flow-change process.
- Define testing requirements.
- Define emergency process.
- Create runbooks.
- Train support teams.
- Establish operational metrics.

## Deliverables

- Architect operations runbook
- Flow support procedure
- Change process
- Troubleshooting guide
- Escalation matrix
- Release procedure

## Acceptance Criteria

BAU teams can independently perform standard Architect administration and support activities.

## Definition of Done

Architect operations are documented, owned and handed over.
