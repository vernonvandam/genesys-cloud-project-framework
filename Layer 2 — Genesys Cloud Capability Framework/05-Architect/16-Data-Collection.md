# Layer 2.05.16 — Data Collection

## Purpose

Collect customer information through Architect.

## Classification

**Required**

## Examples

- Customer number
- Account number
- Postcode
- Date of birth
- Reference number
- Case number
- PIN
- Transaction number

## Activities

- Identify required data.
- Define validation.
- Define input mechanism.
- Define retries.
- Define error handling.
- Configure collection.
- Test valid values.
- Test invalid values.

## Acceptance Criteria

Required data is collected and validated correctly.

## Definition of Done

Data collection components are operational.
