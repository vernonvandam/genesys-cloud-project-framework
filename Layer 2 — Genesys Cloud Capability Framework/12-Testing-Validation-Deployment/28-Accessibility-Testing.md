# 28 — Accessibility Testing

## Capability Definition

Validates accessibility of customer, agent and administrative experiences against applicable accessibility standards and organisational requirements.

---

# 1. Scope

- Agent UI
- Customer journeys
- Digital channels
- Keyboard navigation
- Screen readers
- Visual accessibility
- Audio prompts

---

# 2. Classification

**Conditional**

---

# 3. Discovery Activities

- Identify accessibility requirements.
- Identify applicable standards.
- Identify affected channels.
- Identify accessibility personas.

---

# 4. Design Activities

- Define accessibility scenarios.
- Define assistive technology tests.
- Define keyboard tests.
- Define visual tests.
- Define accessibility acceptance criteria.

---

# 5. Implementation Activities

```text
Review accessibility requirements
Test keyboard navigation
Test screen-reader compatibility
Test focus behaviour
Test labels
Test contrast where applicable
Test accessible prompts
Test digital accessibility
Record issues
Remediate defects
Retest
```

---

# 6. Dependencies

- Digital
- Voice
- Agent Experience
- UI
- Customer Requirements

- Phase 8 — Testing & Validation

- Test Analyst

---

# 9. Customer Responsibilities

- Define standards.
- Provide accessibility requirements.
- Validate outcomes.

---

# 10. Testing

Execute representative accessibility scenarios.

---

# 11. Deliverables

- Accessibility Test Cases
- Accessibility Results
- Defect Register

---

# 12. Effort Drivers

- Number of channels
- Accessibility standards
- Assistive technologies
- Digital complexity

---

# 13. Acceptance Criteria

- Required accessibility scenarios pass.
- Exceptions documented.
- Critical defects resolved.

---

# 14. Definition of Done

Accessibility requirements are validated or formally accepted as exceptions.
