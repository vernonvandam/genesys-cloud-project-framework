# 10 — Unit / Component Testing

## Capability Definition

Validates individual Genesys Cloud configuration components and custom implementation components before integrated testing.

---

# 1. Scope

- Configuration components
- Architect components
- Routing components
- Data Actions
- Scripts
- Integrations
- APIs
- Custom components

---

# 2. Classification

**Required**

---

# 3. Discovery Activities

- Identify testable components.
- Identify component owners.
- Identify component dependencies.
- Identify component acceptance criteria.

---

# 4. Design Activities

- Define component test cases.
- Define positive scenarios.
- Define negative scenarios.
- Define expected outcomes.
- Define evidence requirements.

---

# 5. Implementation Activities

```text
Identify component
Review component design
Prepare test data
Execute positive test
Execute negative test
Validate expected result
Capture evidence
Record defects
Remediate defects
Retest
Approve component
```

---

# 6. Dependencies

- Configuration
- Architect
- Integrations
- Test Data
- Test Accounts

---

# 7. Layer 1 Mapping

Primary:

- Phase 7 — Component & Integration Testing
- Phase 8 — Testing & Validation

---

# 8. Roles

- Genesys Cloud Engineer
- Integration Engineer
- Test Analyst
- Solution Architect

---

# 9. Customer Responsibilities

- Validate business outcomes where required.
- Provide component SMEs.

---

# 10. Testing

Component testing confirms individual components operate correctly before end-to-end integration.

---

# 11. Deliverables

- Component Test Cases
- Execution Results
- Evidence
- Defect Records

---

# 12. Effort Drivers

- Number of components
- Component complexity
- Integration dependencies
- Negative test scenarios

---

# 13. Acceptance Criteria

- Component tests executed.
- Expected results achieved.
- Defects recorded.
- Critical defects resolved.

---

# 14. Definition of Done

All required components pass unit/component testing.
