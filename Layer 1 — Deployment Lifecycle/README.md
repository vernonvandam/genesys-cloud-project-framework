# Layer 1 — Deployment Lifecycle

## Status

**Complete**

## Purpose

Layer 1 defines the end-to-end lifecycle for a Genesys Cloud implementation, from project initiation through production deployment, hypercare, BAU handover and formal project closure.

Layer 1 answers:

> **When does the work happen?**

It provides the master project-management backbone upon which all other methodology layers depend.

## 12-Phase Lifecycle

1. Project Initiation & Mobilisation
2. Discovery & Current-State Assessment
3. Requirements & Solution Definition
4. Solution Architecture & Detailed Design
5. Platform Foundation & Environment Build
6. Feature Configuration & Solution Build
7. Integration & Data Migration
8. Testing & Validation
9. Operational Readiness & Cutover Preparation
10. Production Deployment & Go-Live
11. Hypercare & Stabilisation
12. BAU Handover & Project Closure

## Primary Outputs

- Project lifecycle
- Phase definitions
- Phase dependencies
- Phase entry criteria
- Phase exit criteria
- Phase gates
- Project activities
- Deliverables
- Roles
- Customer responsibilities
- Risks
- Effort considerations
- Definition of Done

## Relationship to Other Layers


## Future Development

Layer 1 should not be substantially restructured unless lessons learned from later layers identify missing lifecycle activities.

Future work should primarily:

- Refine tasks.
- Add dependencies.
- Add effort estimates.
- Add capability references.
- Add role mappings.
- Add acceptance criteria.
- Add spreadsheet identifiers.

## Definition of Done

Layer 1 is complete when the twelve-phase lifecycle can be used as the master project schedule structure and every task from Layers 2–9 can be mapped to one or more Layer 1 phases.
