# Phase 01 — Project Initiation & Mobilisation

## 1. Purpose

Establish the project, governance, scope, delivery framework, responsibilities, and working practices required to successfully deliver a Genesys Cloud implementation.

This phase creates the foundation for all subsequent project phases and ensures that the implementation team and customer have a shared understanding of scope, ownership, governance, assumptions, constraints, and success criteria.

---

## 2. Phase Objective

By the end of Phase 01:

- The project team is formally established.
- Project scope and objectives are understood and documented.
- In-scope Genesys Cloud products and capabilities are identified.
- Project governance and communication mechanisms are established.
- Customer and implementation responsibilities are defined.
- Initial risks, assumptions, issues, dependencies, and constraints are documented.
- The initial project schedule and delivery approach are established.
- The project is ready to commence discovery.

## 5. Phase Gate — Gate 01: Project Mobilised

### Entry Criteria

- Contract / SOW available.
- Project authorised.
- Initial project stakeholders identified.

### Exit Criteria

Phase 01 is complete when:

- Project team is established.
- Project governance is established.
- Project scope is understood.
- Initial Genesys Cloud feature scope is identified.
- Customer and implementation responsibilities are documented.
- Initial assumptions and constraints are documented.
- Initial RAID register is established.
- Initial project schedule is established.
- Project documentation repository is established.
- Project success criteria are agreed.
- Discovery activities can commence.

### Gate Decision

**Gate 01 — PROJECT MOBILISED**

**Status options:**

- PASS — Ready for Discovery
- PASS WITH CONDITIONS — Discovery may proceed with documented actions
- HOLD — Outstanding mobilisation requirements
- FAIL — Project not ready to proceed

## 8. Important Methodology Principle

Phase 01 establishes the project framework but does **not** attempt to fully define the solution.

Detailed requirements, feature decisions, technical architecture, configuration design, and implementation sequencing are progressively established in later phases.

The intended lifecycle is:

**Phase 01 — Mobilise**
→ **Phase 02 — Discover**
→ **Phase 03 — Define Requirements**
→ **Phase 04 — Design**
→ **Phase 05 — Establish Foundation**
→ **Phase 06 — Build**
→ **Phase 07 — Integrate & Migrate**
→ **Phase 08 — Test**
→ **Phase 09 — Prepare for Go-Live**
→ **Phase 10 — Deploy**
→ **Phase 11 — Hypercare**
→ **Phase 12 — Handover & Close**

This separation prevents premature technical decisions and provides a controlled transition from project initiation through to implementation.
