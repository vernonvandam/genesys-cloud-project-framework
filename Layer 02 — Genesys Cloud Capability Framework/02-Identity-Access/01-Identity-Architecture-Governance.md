# Layer 2.02.01 — Identity Architecture & Governance

## 1. Purpose

Define the overall identity architecture, ownership and governance model for the Genesys Cloud implementation.

## 2. Scope

- Identity authority
- Identity ownership
- IAM integration
- Authentication architecture
- User lifecycle
- Administrative ownership
- Security governance
- Access standards

## 3. Classification

**Required**

## 4. Discovery

Determine:

- Authoritative identity source.
- Customer IAM platform.
- Existing SSO architecture.
- Authentication standards.
- MFA standards.
- User lifecycle process.
- Privileged-access standards.
- Security ownership.
- Compliance requirements.
- Existing Genesys Cloud organisation.

## 5. Design Activities

1. Document current-state identity architecture.
2. Define target-state architecture.
3. Define identity ownership.
4. Define authentication authority.
5. Define provisioning authority.
6. Define administrator model.
7. Define privileged-access model.
8. Define identity integration boundaries.
9. Define audit requirements.
10. Obtain architecture approval.

## 6. Dependencies

- Core Platform
- Customer IAM
- Security architecture
- Organisation structure
- Licensing

## 7. Layer 1 Mapping

Primary:

- Phase 2 — Discovery
- Phase 4 — Architecture

Supporting:

- Phase 5 — Platform Foundation
- Phase 9 — Operational Readiness

## 8. Roles

- Solution Architect
- Security Architect
- IAM Architect
- Genesys Cloud Architect
- Customer Security Owner

## 9. Customer Responsibilities

- Provide IAM architecture.
- Confirm security policies.
- Approve target architecture.
- Identify identity owners.
- Confirm compliance requirements.

## 10. Deliverables

- Identity architecture
- IAM responsibility matrix
- Identity governance model
- Architecture decision record

## 11. Risks

- IAM requirements discovered too late.
- Incorrect identity ownership.
- Unsupported authentication design.
- Excessive administrative access.

## 12. Effort Drivers

- Existing IAM maturity
- SSO complexity
- Multiple organisations
- Regulatory requirements
- Automation
- Customer security controls

## 13. Acceptance Criteria

The target identity architecture is documented and approved by customer security and architecture stakeholders.

## 14. Definition of Done

Identity architecture, ownership, governance and security principles are approved and incorporated into the project design.
