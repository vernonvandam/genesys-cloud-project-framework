# 33 — Regression Testing

## Capability Definition

Validates that changes, defect fixes, configuration updates or releases have not adversely affected existing functionality.

---

# 1. Scope

- Functional regression
- Integration regression
- Routing regression
- Architect regression
- Telephony regression
- Digital regression
- Reporting regression

---

# 2. Classification

**Required**

---

# 3. Discovery Activities

- Identify critical functionality.
- Identify regression candidates.
- Identify previous defects.
- Identify high-risk areas.

---

# 4. Design Activities

- Define regression suite.
- Define risk-based regression.
- Define automation candidates.
- Define regression entry/exit criteria.

---

# 5. Implementation Activities

```text
Identify regression scope
Select regression test cases
Prepare environment
Prepare test data
Execute regression
Compare results
Record failures
Investigate impact
Remediate defects
Retest
Approve regression
```

---

# 6. Dependencies

- Test Cases
- Defect Management
- Configuration Changes
- Release Management

---

# 7. Layer 1 Mapping

Primary:

- Phase 8 — Testing & Validation
- Phase 10 — Production Deployment & Go-Live

---

# 8. Roles

- Test Lead
- Test Analyst
- Genesys Cloud Engineer
- Integration Engineer

---

# 9. Customer Responsibilities

- Identify critical business functions.
- Validate regression results.

---

# 10. Testing

Regression must cover high-risk and business-critical functionality.

---

# 11. Deliverables

- Regression Suite
- Regression Results
- Regression Sign-Off

---

# 12. Effort Drivers

- Regression suite size
- Change scope
- Integration count
- Automation level

---

# 13. Acceptance Criteria

- Required regression executed.
- Critical functions pass.
- Defects resolved or accepted.

---

# 14. Definition of Done

Regression testing is complete with formal approval.
