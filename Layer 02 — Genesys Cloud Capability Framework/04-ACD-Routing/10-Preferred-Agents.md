# Layer 2.04.10 — Preferred Agents

## 1. Purpose

Determine whether interactions should preferentially route to a specific agent or agent group based on business requirements.

## 2. Classification

**Conditional**

## 3. Use Cases

- Existing customer relationships
- Account ownership
- Case continuity
- VIP servicing
- Specialist relationships

## 4. Activities

- Identify preferred-agent use cases.
- Define eligibility.
- Define fallback.
- Configure required behaviour.
- Test preferred agent available.
- Test preferred agent unavailable.
- Test fallback.

## 5. Acceptance Criteria

Preferred-agent behaviour operates without negatively impacting service levels.

## 6. Definition of Done

Preferred-agent strategy is configured, tested and documented.
