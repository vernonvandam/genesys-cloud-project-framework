# Layer 2.04.01 — ACD Routing Architecture

## 1. Purpose

Define the target-state ACD routing architecture across all supported interaction types.

## 2. Classification

**Required**

## 3. Scope

- Routing architecture
- Queue model
- Interaction types
- Routing methods
- Skills
- Priority
- Agent eligibility
- Overflow
- In-queue handling
- Service levels
- Reporting dependencies

## 4. Discovery Questions

- What interaction types require ACD routing?
- How many business functions require queues?
- What determines the destination queue?
- Are skills required?
- Is language-based routing required?
- Are customers prioritised?
- Are VIP customers treated differently?
- Is preferred-agent routing required?
- Are there existing routing rules?
- What happens when no agent is available?
- What are the service-level objectives?
- Are there different routing rules by geography?
- Are routing rules channel-specific?
- Are there regulatory requirements?
- Are queues shared across business units?

## 5. Activities

1. Document current-state routing.
2. Inventory queues.
3. Inventory routing rules.
4. Identify interaction types.
5. Identify routing criteria.
6. Define queue architecture.
7. Define routing strategy.
8. Define skills strategy.
9. Define priority.
10. Define overflow.
11. Define in-queue handling.
12. Define agent eligibility.
13. Define operational model.
14. Obtain architecture approval.

## 6. Dependencies

- Voice & Telephony
- Digital

- Business requirements

## 7. Layer 1 Mapping

## 8. Deliverables

- ACD architecture
- Routing strategy
- Queue model
- Routing decision matrix

## 9. Acceptance Criteria

Target-state routing architecture is approved.

## 10. Definition of Done

Routing architecture and associated design decisions are documented and approved.
