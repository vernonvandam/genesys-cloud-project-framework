# Layer 2.05.19 — Data Actions

## Purpose

Integrate Architect with external systems and APIs.

## Classification

**Conditional**

## Scope

- CRM
- Customer systems
- Authentication
- Account lookup
- Case management
- Payments
- Notifications
- External business rules
- Middleware

## Activities

1. Identify integration requirement.
2. Define API.
3. Define authentication.
4. Define request.
5. Define response.
6. Define timeout.
7. Define error handling.
8. Configure Data Action.
9. Test success.
10. Test failure.
11. Test timeout.
12. Validate security.

## Acceptance Criteria

The Data Action reliably provides the required data or business operation.

## Definition of Done

Data Action is production-ready and documented.
